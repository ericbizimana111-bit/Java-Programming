Question 19: Explain why ClassNotFoundException may occur when deserializing an object
First, understand that a serialized file contains more than just the visible field values. Java's serialization format also identifies the classes needed to reconstruct the object.

For example, imagine you save a Student object to student.dat.

Later, you run a different program and execute:
Student student = (Student) input.readObject();


For Java to reconstruct the student, it must be able to locate and load the required Student class.
Why can ClassNotFoundException happen?
It may happen when:
- The required class is missing from the runtime classpath.
- The class was moved, renamed, or is no longer available in the expected package.
- A class needed to reconstruct the object cannot be loaded.
For example, the saved object refers to:
school.Student


But the program no longer has the school.Student class available. Java cannot load the class needed to reconstruct the object.
How can we prevent or fix it?
1. Ensure that the required class files or library are available when running the program.
2. Keep the class's fully qualified name consistent when you need to read old serialized data.
3. Check the classpath and package declarations.
4. Maintain serialization compatibility when changing classes.
A useful distinction: ClassNotFoundException is different from InvalidClassException. The first concerns Java being unable to locate a required class; the second can occur when the class exists but its serialization version is incompatible with the saved stream.

Also, readObject() can throw ClassNotFoundException, so Java requires you to handle or declare that checked exception.

Java Deserialization and ClassNotFoundException — Complete Explanation
Let us learn this topic from the beginning, step by step, with Java code examples, explanations of every important line, common errors, and exercises to help you prepare for your exam.

The most important thing to understand is this:

Java serialization saves an object's state, while deserialization uses that saved state to reconstruct the object. For deserialization to work, Java must be able to find the class of the object being restored.

1. First, understand the basic concepts
What is an object?
An object is an instance of a class. For example, imagine that we have a Student class.

class Student {
    String name;
    int age;
}

The class describes what a student has: a name and an age.

We can create an object like this:

Student student = new Student();
student.name = "Eric";
student.age = 22;

Here:

Student is the class.

student is a reference variable.

new Student() creates an object.

"Eric" and 22 are values stored in the object's fields.

Now imagine that we want to save this object's information into a file so that we can use it later. This is where serialization comes in.

What is serialization?
Serialization is the process of converting an object's state into a format that can be saved to a file or transmitted over a network.

For example, we want to save the following information:

Object in memory

Student object

name = "Eric"

age = 22

Serialization

student.dat

Saved binary data representing the object's state and class information.

Java does not normally save the object as readable text such as name=Eric, age=22. It writes a binary representation of the serialized object.

What is deserialization?
Deserialization is the reverse process: Java reads the serialized data and reconstructs an object from it.

student.dat

Previously saved serialized data

Deserialization

Reconstructed Student object

name = "Eric"

age = 22

Java must know what a Student is before it can reconstruct a Student object. If it cannot locate the required class, deserialization may fail with ClassNotFoundException.

2. What exactly is ClassNotFoundException?
ClassNotFoundException is a checked exception in Java. It indicates that Java attempted to load a class by name but could not find the required class definition.

For example, imagine that your serialized file contains data for an object belonging to this class:

package school;

public class Student implements java.io.Serializable {
    String name;
    int age;
}

The fully qualified class name is:

school.Student
The fully qualified name combines the package name and the class name.

Now imagine that you try to read the object, but the school.Student class is not available to the program.

Object obj = input.readObject();

Java tries to load school.Student, but it cannot find the class. The deserialization operation can therefore throw:

java.lang.ClassNotFoundException: school.Student
Why does this happen? The saved file contains information about the class, but it does not automatically provide Java with the compiled class definition needed to load and reconstruct that object.

Think of it like having a recipe for a meal but not having access to the instructions that explain what the ingredients and cooking steps mean. The saved information alone is not enough.

3. Before we write the code, understand Serializable
In Java, a class must support serialization before its objects can normally be serialized using ObjectOutputStream.

We do this by implementing the Serializable interface.

import java.io.Serializable;

class Student implements Serializable {
    String name;
    int age;
}

Let us understand the important line:

class Student implements Serializable

class Student declares a class named Student.

implements indicates that the class implements an interface.

Serializable is a marker interface. It tells Java's serialization mechanism that objects of this class are eligible for default serialization.

A marker interface does not require you to implement methods. Serializable has no methods to implement.

If you omit implements Serializable, attempting to serialize a Student object using ObjectOutputStream will normally cause a different exception: NotSerializableException.

Remember the difference:

Exception

Meaning

NotSerializableException

You tried to serialize an object whose class does not support serialization.

ClassNotFoundException

During deserialization, Java cannot load a required class.

InvalidClassException

A class was found, but a serialization compatibility check failed.

These exceptions happen for different reasons.

4. Complete Java example: serialize and deserialize a Student
We will write a complete program that saves a student to a file and then reads the student back.

Create a Java file named StudentSerializationDemo.java.


import java.io.FileOutputStream;
import java.io.FileInputStream;
import java.io.ObjectOutputStream;
import java.io.ObjectInputStream;
import java.io.IOException;
import java.io.Serializable;

class Student implements Serializable {

    private static final long serialVersionUID = 1L;

    String name;
    int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    void display() {
        System.out.println("Name: " + name);
        System.out.println("Age: " + age);
    }
}

public class StudentSerializationDemo {

    public static void main(String[] args) {

        // Step 1: Create an object
        Student student = new Student("Eric", 22);

        // Step 2: Serialize the object and save it
        try (ObjectOutputStream output =
                 new ObjectOutputStream(
                     new FileOutputStream("student.dat"))) {

            output.writeObject(student);

            System.out.println("Student saved successfully.");

        } catch (IOException e) {
            System.out.println("Error saving student: "
                    + e.getMessage());
        }

        // Step 3: Deserialize the object
        try (ObjectInputStream input =
                 new ObjectInputStream(
                     new FileInputStream("student.dat"))) {

            Student restoredStudent =
                    (Student) input.readObject();

            System.out.println("\nStudent restored:");
            restoredStudent.display();

        } catch (IOException e) {
            System.out.println("Error reading student: "
                    + e.getMessage());

        } catch (ClassNotFoundException e) {
            System.out.println("Required class not found: "
                    + e.getMessage());
        }
    }
}

Step-by-step explanation of the code
Step 1: Create a student object

Student student = new Student("Eric", 22);

This creates a Student object in memory.

Its fields contain:

name = "Eric"
age  = 22
At this stage, the object exists in memory. We have not saved it to a file yet.

Step 2: Create the output stream

new FileOutputStream("student.dat")

This opens a file for writing bytes. If the file does not exist, Java normally creates it. If it already exists, its contents are overwritten.

new ObjectOutputStream(
    new FileOutputStream("student.dat")
)

ObjectOutputStream wraps the file output stream and provides the writeObject() method for serializing objects.

Step 3: Save the object

output.writeObject(student);

This is the line that serializes the student object and writes its serialized representation to student.dat.

Step 4: Open the saved file for reading

new FileInputStream("student.dat")

This opens the file for reading bytes.

new ObjectInputStream(
    new FileInputStream("student.dat")
)

ObjectInputStream reads serialized object data.

Step 5: Restore the object

Student restoredStudent =
        (Student) input.readObject();

This is the most important line for Question 19.

Let us divide it into three parts.

input.readObject() reads the serialized data and attempts to reconstruct the object. Its return type is Object.

(Student) casts the returned reference to the Student type.

restoredStudent stores the reference to the reconstructed student.

Notice that the cast does not find or load the class for you. Java must successfully reconstruct the object before the cast can be completed.

The readObject() method declares ClassNotFoundException, which is why we handle that exception in a separate catch block.

Step 6: Close the streams

try (ObjectInputStream input = ...) {
    // Read the object
}

This is called try-with-resources. Java automatically closes the stream when execution leaves the block, including when an exception occurs.

Expected output
Student saved successfully.

Student restored:
Name: Eric
Age: 22
The file student.dat is created in the program's working directory. It contains binary data, so do not expect to read it as an ordinary text file.

How to run it
If you are using a terminal, navigate to the folder containing the source file and run:

javac StudentSerializationDemo.java
java StudentSerializationDemo

Run the program in the same folder so that it can find student.dat easily.

5. Now, how can we actually cause ClassNotFoundException?
This is the central part of your exam question.

In our previous example, the Student class is available because it is declared in the same source file. Java can load it, so deserialization succeeds.

To understand the exception, imagine a different situation.

Program A: Saving

The Student class exists. Java serializes the object and saves it to student.dat.

The file is moved

The file contains the serialized representation and class-identification information, but it is not a replacement for the compiled class.

Program B: Reading

The program tries to restore the student, but the required Student class is missing from the classes available to its class loader. Deserialization fails.

There is one important detail: you cannot reliably reproduce this exception merely by deleting a .java source file if the compiled .class file is still available. Java runs compiled classes, not source files by default.

To demonstrate the error properly, we can use two separate programs and remove the required class from the reader's runtime classpath.

Example: Two separate programs
We will create one program to save the object and another program to read it.

Program A — SaveStudent.java
import java.io.Serializable;
import java.io.FileOutputStream;
import java.io.ObjectOutputStream;
import java.io.IOException;

class Student implements Serializable {
    private static final long serialVersionUID = 1L;

    String name = "Eric";
    int age = 22;
}

public class SaveStudent {
    public static void main(String[] args)
            throws IOException {

        Student student = new Student();

        try (ObjectOutputStream out =
                 new ObjectOutputStream(
                     new FileOutputStream("student.dat"))) {

            out.writeObject(student);
            System.out.println("Student saved.");
        }
    }
}

Compile and run this program:

javac SaveStudent.java
java SaveStudent

It creates student.dat.

Program B — ReadStudent.java
This program does not refer to the Student class in its source code. That lets us compile and run it even when the Student class is unavailable.

import java.io.FileInputStream;
import java.io.ObjectInputStream;
import java.io.IOException;

public class ReadStudent {
    public static void main(String[] args) {

        try (ObjectInputStream in =
                 new ObjectInputStream(
                     new FileInputStream("student.dat"))) {

            Object obj = in.readObject();

            System.out.println("Object restored.");

        } catch (ClassNotFoundException e) {
            System.out.println(
                "Cannot restore object: " + e.getMessage());

        } catch (IOException e) {
            System.out.println(
                "File error: " + e.getMessage());
        }
    }
}

How to reproduce the error
For a controlled demonstration, use this folder arrangement:

SerializationDemo/
├── writer/
│   ├── SaveStudent.java
│   ├── Student.class
│   ├── SaveStudent.class
│   └── student.dat
└── reader/
    └── ReadStudent.java
Compile and run SaveStudent.java inside writer.

Put a copy of student.dat inside reader.

Compile ReadStudent.java inside reader.

Run ReadStudent with only the reader folder on the runtime classpath.

From the SerializationDemo folder, you can use the following commands if your Java environment supports the standard directory layout shown above:

javac writer/SaveStudent.java
java -cp writer SaveStudent

Copy writer/student.dat to reader/student.dat, then run:

javac reader/ReadStudent.java
java -cp reader ReadStudent

The reader does not have access to Student.class. When readObject() encounters the serialized class name Student, it cannot load that class, so you should see an error similar to:

Cannot restore object: Student
The exact message can vary depending on the Java version and class-loading details. The important point is that the exception is ClassNotFoundException.

How to fix it: Put the required class or its library back on the reader's runtime classpath. For example, running the reader with both the reader and writer folders available would allow it to find Student.class:

java -cp reader:writer ReadStudent

On Windows, use a semicolon instead of a colon:

java -cp "reader;writer" ReadStudent

Now Java can load Student, and deserialization should succeed.

6. Why is ClassNotFoundException different from InvalidClassException?
This is a common exam question because both exceptions can happen during deserialization.

Situation

Exception

The class required by the serialized data cannot be loaded.

ClassNotFoundException

The class is available, but its serialization version is incompatible with the saved data.

InvalidClassException

Consider this example:

private static final long serialVersionUID = 1L;

The serialVersionUID is a version identifier used in serialization compatibility checks.

Suppose you serialize an object when its class has:

private static final long serialVersionUID = 1L;

Later, you change the class to:

private static final long serialVersionUID = 2L;

If you then try to deserialize the old data using the new class, Java normally throws InvalidClassException because the version identifiers do not match.

By contrast, if the class is completely missing from the runtime classpath, Java may throw ClassNotFoundException.

Changing serialVersionUID is not a solution to a missing class. You need to make the class available.

7. What if the class was renamed or moved to another package?
Suppose the original class was:

package school;

public class Student implements java.io.Serializable {
    private static final long serialVersionUID = 1L;
    String name;
}

The serialized object identifies its class as school.Student.

Later, you move it to a new package:

package university;

public class Student implements java.io.Serializable {
    private static final long serialVersionUID = 1L;
    String name;
}

Its fully qualified name is now university.Student.

Even though both classes are named Student, they are different class names from Java's perspective. The old serialized data still identifies school.Student.

If the old class is unavailable, deserialization may fail with ClassNotFoundException.

How to prevent this problem:

Keep the required class available when reading saved objects.

Avoid changing class names and packages without considering previously saved data.

Keep class definitions compatible when possible.

For long-lived data, consider explicit versioning and migration strategies rather than relying on Java serialization indefinitely.

8. Why must we handle ClassNotFoundException?
Consider this line:

Object obj = input.readObject();

The method readObject() declares ClassNotFoundException in its method signature. Since it is a checked exception, Java requires you to catch it or declare it.

One way is to use try-catch:

try {
    Object obj = input.readObject();

} catch (ClassNotFoundException e) {
    System.out.println("Required class is missing.");
}

Another way is to declare it:

public static void main(String[] args)
        throws Exception {
    // Deserialization code
}

The second example is shorter, but catching the specific exception is often better for learning and for handling the problem appropriately in a real application.

Also remember that handling the exception does not automatically repair the problem. It allows your program to respond gracefully. You must still make the missing class available to successfully restore the object.

10. Final exam-ready answer
Question 19: Explain why ClassNotFoundException may occur when deserializing an object.

ClassNotFoundException may occur during deserialization when Java cannot locate or load a class required to reconstruct a serialized object. This can happen when the class is missing from the runtime classpath, has been renamed or moved to another package, or a required dependency is unavailable. For example, if an object of class school.Student is saved to a file and the school.Student class is not available when ObjectInputStream.readObject() is called, Java may throw ClassNotFoundException. The problem can be fixed by ensuring that the required class and dependencies are available and correctly configured on the runtime classpath. The exception must also be caught or declared because it is a checked exception.

The key idea to remember: Saving an object does not mean saving all the compiled class definitions needed to reconstruct it. During deserialization, Java needs both the serialized data and access to the required class definitions.
